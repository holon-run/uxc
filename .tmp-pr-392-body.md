## What
Add end-to-end coverage for the MCP HTTP initialize/initialized lifecycle on the default daemon-backed CLI path.

## Why
The default `uxc <endpoint> ...` flow uses the daemon, so adapter-only coverage is not enough to prevent regressions in the real user path.

Closes #392

## How
Tighten the `requires_initialized_ack` HTTP test server scenario to track initialized state per MCP session, then exercise both daemon autostart host-help and daemon-backed tool execution against that stricter lifecycle contract.

## Changes

- [x] Track `notifications/initialized` per MCP HTTP session in the local test server
- [x] Make the `requires_initialized_ack` scenario issue a session id during `initialize`
- [x] Assert daemon usage and daemon autostart in the existing local CLI lifecycle tests
- [x] Add daemon E2E coverage for autostarted host-help against a server that requires `notifications/initialized`
